# What stays when the model changes

> A narrated talk that sorts the five things CompanyGraph calls a model into what a company keeps and what it can replace, and ends on the practices that follow.

## Achievements

### Context

- Gave it on Oct 4, 2026 as a talk on companygraph.io, built on four layers and one rule: each decision goes to the lowest layer that can make it, code first, then System One, then System Two, then a person.

### Ways of working

- Fixed the frame one decision at a time before the deck was drafted, and dropped a third frame of maturity levels that had been considered, so the talk carries one rule and not two.
- Credited the ideas it borrows on a slide of their own: TypeSafe, who call their decision model Jev a System One model, and System One and System Two as Stanovich and West first named them and Kahneman made them known.
- Put the page the talk rests on into the model before the deck: the feature on a decision model asking each page its schema's writing rules, named for the capability and not the vendor that supplies it.

### Sharing

- Opened on the word itself: around CompanyGraph a model names five things, two of them models that learned and three of them files a company keeps, the meta-model, its own mental model and the graph drawn from it.
- Gave each layer its job: the check decides what code can prove, the System One judge turns each writing rule into a typed question and advises without changing anything, the System Two models draft and read, and the Owner's word merges, because a pass that finds nothing approves nothing.
- Marked each replaceable part as replaceable today or by design, the agent over MCP and the editor today, the System One and System Two models and the graph database by design, against what stays fixed: the meta-model, the mental model, the check, the rules and decisions and a person's approval.
- Showed why a model is pinned and measured against the same company before a newer one is named, from the one file where the tooling names its judge.
- Closed on six practices and one line: the model you will change most often is the one you should depend on least, so the next one is a pin you move and not a project you start.
- Named on every slide the pages of the model it rests on, so a listener can check each claim against the source.
- Published it as a self-contained bilingual deck with a transport bar, narration recorded from the speaker notes in each language and a PDF of each.
